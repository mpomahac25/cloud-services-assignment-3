1. Why are so many companies using cloud-based email and calendar services?

One of the biggest reasons is that using a cloud-based email and calendar service, such as Microsoft's Outlook, is that they require almost no maintenance compared to hosting those services locally. This means that things like server maintenance, installing updates, providing core security features, and ensuring redundancy is being handled by the provider of these services.

Another advantage is scalability. If the company recruits a lot of new people, they usually just need to create an account for them and set any permission levels (if applicable). Any other system-related things, such as expanding the amount of resources available for handling the email traffic and accounts, is once again handled by the provider of the service.

And a third advantage is convenience. A cloud-based service ensures that employees are able to access their emails and calendars from anywhere as long as they have an internet connection, without such a setup requiring the IT department of the company to do a long and complex setup to ensure the same level of access and security themselves.

2. When should you maintain your own web server and when should you use SaaS, PaaS or IaaS?

Maintaining your own server makes sense in specific cases, such as when you want to have a high level of control over the hardware, OS, or network, or when there are potential security requirements or goals with doing so. Another possible reason to use your own server instead of a cloud service is if the costs of the hardware and electricity end up being lower over time than the cost of the cloud service.

However, if none of the above are the case, it almost always means that it would make more sense to use a cloud service, with the specific type depending on the required level of control you want or need over the whole system.

3. Public DNS resolvers vs. ISP DNS resolvers

A public DNS resolver often provides better performance, security, and reliability than some ISP-provided DNS services. However, this can sometimes cause an issue with services which use DNS to choose the closes CDN location. Normally, a CDN tries to direct the user to a nearby "edge server" which stores cached copies of websites. But if the CDN is being determined based on the DNS resolver's location, and that DNS resolver is geographically far away from the user, the selected edge server might not be close to the user. This can introduce increased latency or even request timeouts in extreme cases.

With an ISP-provided DNS service, the geographical distance is usually relatively short, making the above scenario far less likely. However, an ISP-provided DNS service can have its own disadvantages, such as potentially weaker or inconsistent security level, reliability and performance issues, and filtering of certain DNS responses (effectively blocking certain websites).

4. Why do many IoT devices use public DNS resolvers?

Public DNS resolvers are more likely to be reliable, which is going to be attractive to many manufacturers of IoT devices. This greatly reduces the risk of their products not working due to an unreliable DNS server being used by the local network's router.

However, depending on the configuration of the network policies, access to external DNS servers might be blocked by the local network, which would again lead to the same issue. In addition, using a public DNS takes control away from the network administrator and creates a potential vulnerability if the device is ever compromised, as any DNS filtering configured in the DNS server used by the local network's router will be bypassed by the IoT device using a public DNS server.

Due to the risks assoicated with using a public DNS resolver in IoT devices, it's actually recommended by IETF to use the DNS resolver provided by the local network instead of depending on public resolvers for IoT devices.
